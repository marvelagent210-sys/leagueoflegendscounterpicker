# Data

Generated by `npm run build:data`; don't edit these files by hand. `raw/` holds the downloaded sources and isn't committed. Each patch folder has `champions.json` (base stats), `abilities/` (one JSON file per champion), `glossary.json` (the wiki's lists of abilities by mechanic), `rules.json` (stat gold values for the simulator's stat budget), `profiles/` (what each ability does in a fight), `counters/` and `rankings.json` (the interaction ledger's counter rankings, partial until the duel simulator), `kits/` (readable pages for checking), `oracle/` (the wiki's level-20 table used by the tests) and `reports/`.

## License

The champion data here is derived from the [League of Legends Wiki](https://wiki.leagueoflegends.com/en-us/) and is licensed under [CC BY-SA 3.0](https://creativecommons.org/licenses/by-sa/3.0/), as the wiki's content is. `wiki-revisions.json` in each patch folder lists the exact wiki revision of every page used.

Base stats are cross-checked against the game's data files from [CommunityDragon](https://www.communitydragon.org/); where those state a different value for a champion's base form, it is used instead (listed in `reports/game-files.md`). League of Legends and its game data are property of Riot Games, Inc.

Selected ability records also retain audited supplemental wiki quotations and
versioned CommunityDragon game-file excerpts. Game evidence records its URL,
version, object path and SHA-256 separately from wiki revisions. The kit compiler
rejects missing quotations and unversioned game sources; interpreting a client
field as combat geometry still requires an explicit assumption.

Parsed ability records can explicitly mark a retained template as `historical`. These records remain available for source history but are excluded from current kit lookups, interaction profiles and ability displays. Corki's archived Special Delivery carries the exact versioned client character-registry excerpt used in that review; it is not presented as an extra current W.
